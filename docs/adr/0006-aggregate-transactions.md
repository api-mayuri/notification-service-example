# ADR 0006. Границы транзакций между агрегатами

- **Статус:** принято

## Правило

Каждый агрегат меняется в своей транзакции. Статус уведомления вычисляется из статусов доставок асинхронно: `NotificationStatusListener` (`@ApplicationModuleListener`) вызывает `SynchronizeNotificationStatusUseCase` в новой транзакции после каждого изменения статуса доставки. Это eventual consistency, и событие защищено Event Publication Registry.

## Осознанные исключения

1. **Приём уведомления.** `Notification`, его `Delivery` и записи outbox сохраняются в одной транзакции — этого требует схема потока в промпте. Доставки создаются вместе с уведомлением и до коммита больше никому не видны, поэтому конфликтов нет.
2. **Отмена.** Отмена уведомления и его доставок атомарна. Иначе возможно состояние «уведомление отменено, а доставка уходит». Перед отменой статус пересчитывается по доставкам: если воркер уже начал отправку, возвращается `409`.

## Оптимистическая блокировка

У всех агрегатов есть версия (`@Version` в JPA-сущностях, токен `version` в снимках). Параллельная попытка отправить одну доставку отсекается конфликтом версии: воркер получает `Ignored`.
