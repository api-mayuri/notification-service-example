# ADR 0003. Слой приложения зависит от spring-tx

- **Статус:** принято

## Контекст

Транзакции должны задаваться только на уровне use case. Промпт разрешает слою приложения зависеть от `spring-tx`, но это нужно зафиксировать.

## Решение

`notification-application` зависит от `org.springframework:spring-tx`. Используются:

- `@Transactional` на методах сценариев;
- `TransactionOperations` в `DeliveryProcessingService`: попытка отправки разбита на две короткие транзакции, а сетевой вызов провайдера идёт вне транзакции и не держит соединение с БД;
- `OptimisticLockingFailureException` из `org.springframework.dao` (в jar `spring-tx`), чтобы распознать параллельную обработку одной доставки.

Других зависимостей от Spring нет. Это проверяет ArchUnit.

## Альтернативы

Можно было бы ввести собственный порт `TransactionRunner`. Это не дало бы изоляции (реализация всё равно на Spring), но добавило бы кода. Отклонено по принципу «готовое вместо самописного».
